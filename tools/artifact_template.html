還要
幾步？

How far
is this?

這個網路不知道要轉哪一面。它只會回答一個問題：這個局面離解開還有幾步。 真正把方塊解開的是搜尋。而因為 2×2×2 的正確答案可以整個算出來， 「它猜得有多準」這件事在這裡是量出來的，不是估的。

This network has no idea which face to turn. It answers exactly one question: how many moves is this state from solved. Search does the solving. And because a 2×2×2's ground truth can be enumerated in full, "how wrong is the guess" here is measured, not estimated.

這題不能靠碰運氣

Luck is not an option here

一顆三階魔術方塊有 43,252,003,274,489,856,000 種排列，其中只有一種是解開的。 拿一千個打亂過的方塊，每個亂轉一萬步——解開幾個？零個。 不是機率很低，是實際跑完之後一個都沒有。

A 3×3×3 cube has 43,252,003,274,489,856,000 arrangements and exactly one is solved. Take a thousand scrambled cubes, turn each one ten thousand times at random — how many come out solved? None. Not "rarely". Zero, after actually running it.

這件事把一整類方法排除掉了。前面幾個專案——打磚塊、河內塔——亂走至少偶爾會撞到終點， 撞到了才有東西可以往回傳。魔術方塊撞不到。所以「先隨機探索、嚐到一次成功、再把訊號往回傳」 這條 DQN 的路，在這裡從第一步就是斷的。

That single fact rules out a whole family of methods. In the earlier labs — Breakout, Tower of Hanoi — a random walker does eventually stumble onto the goal, and that first taste of success is what the learning signal propagates back from. Here it never happens. The DQN loop of explore → stumble → backpropagate is broken at step one.

先做一把尺

Build a ruler first

所以先退一步，做一個小的。二階魔術方塊，把 DBL 那顆角固定住之後只剩三個面可以轉 （不固定的話整顆方塊的旋轉會讓同一個局面有 24 種寫法，狀態空間憑空大 24 倍）。 總共 3,674,160 個局面——小到可以整個列出來。

So step down to something smaller. On a 2×2×2 with the DBL corner pinned, only three faces turn (without pinning, whole-cube rotations give every state 24 spellings and inflate the space 24-fold). That leaves 3,674,160 states — few enough to enumerate completely.

從解開狀態做一次廣度優先搜尋，18 秒之後，每一個局面的精確最短步數就全部在手上了。 這張表跟機器學習一點關係都沒有。它是正確答案——是這整個專案的量尺。

One breadth-first sweep from the solved state, eighteen seconds, and the exact optimal distance of every single state is in hand. That table has nothing to do with machine learning. It is the ground truth — the ruler everything else gets measured against.

資料是倒著造出來的

The data is manufactured backwards

這一段跟系列前面五個專案的作法差最多。訓練資料不是玩出來的，是造出來的： 從已經解開的狀態往回亂轉 d 步。往回 d 步的局面，答案一定不超過 d 步—— 所以資料自帶難度標籤，而且要多少有多少。不需要 agent 先會玩才有東西可學。

This is where the project departs hardest from the previous five. Training data isn't played, it's manufactured: take the solved state and walk backwards d random moves. A state d moves back is at most d moves from solved, so every sample arrives with a difficulty label attached, in unlimited supply. Nothing has to be good at the game first.

訓練目標是把每個局面的子節點展開一層，取最小的那個加一：

The regression target expands one layer of children and takes the minimum, plus one:

y(s) = mina [ 1 + htarget( a(s) ) ]

注意這一條跟策略完全無關。不管現在的網路多爛，這個目標永遠是 「所有子節點裡最好的那一個」。河內塔那個專案被爛策略帶壞的 n-step return，在這裡不存在—— 因為這裡根本沒有「行為策略」這個東西。

Note that this is policy-independent. However bad the current network is, the target is still "the best of all children". The n-step return that a weak behaviour policy poisoned in the Hanoi lab simply cannot go wrong here — there is no behaviour policy to be weak.

Plot the network's output against the truth: x is the true optimal distance, y is what the network says, and the orange band is ±1 standard deviation. The line tracks the diagonal, which means it did learn distance rather than memorise particular states.

最後那個數字才是重點：如果不搜尋，每一步就挑網路覺得最近的子節點走， 解開率只有那樣。也就是說——這個網路自己解不開魔術方塊。

The last number is the one that matters: without search, walking greedily to whichever child the network likes best, that's the solve rate. Which is to say — this network cannot solve a Rubik's cube.

另外一半：搜尋

The other half: search

同一個解不開方塊的網路，配上加權 A*，解開率 100%。排序的分數只有一行：

The same network that can't solve a cube, wrapped in weighted A*, solves 100% of them. The whole ranking rule is one line:

f = weight × 已走步數moves so far + h(s)

heuristic 不需要準，只要方向大致對，搜尋就會把細節補回來。這就是為什麼「學價值」比 「學策略」在這題上合理：一個 90% 正確的策略走 20 步，全對的機率只有 12%，錯一步就前功盡棄； 而一個「大概準」的距離估計配上搜尋，錯了可以退回來重試。

The heuristic doesn't need to be right, only to point roughly the right way; search fills in the rest. That's why learning value beats learning policy here: a policy that's 90% correct over 20 moves is fully correct only 12% of the time, and one wrong move throws the whole thing away. A roughly-correct distance estimate plus search can back up and try again.

直覺會說：weight 調到 0 就是純貪婪，最快，但解最長。後半對，前半錯。 weight=0 的解平均要 步（最短解只要 步），而且它展開的節點比中間那個設定還多： vs 。 一路往網路覺得近的方向衝，會衝進死路，繞出來的成本比一開始就多想兩步還貴。 真正的甜蜜點在中間。

Intuition says weight 0 is pure greed: fastest, longest solutions. The second half is right; the first half is not. At weight 0 the solutions average moves against an optimum of — and it expands more nodes than the balanced setting, against . Charging at whatever looks closest walks into dead ends, and backing out of them costs more than thinking two moves further ahead would have. The sweet spot is in the middle.

這個歸因另外驗過。A* 還有一個經典陷阱：終點如果在「產生子節點」時就判定、而不是等它被「展開」， 那即使 heuristic 完全 admissible 也可能回傳非最短解。兩種寫法都跑過同樣 500 個局面—— 最短解率都是 99.2%，而且失敗的是同樣那 4 個局面，所以跟判定時機無關。 另外，那 4 個全都剛好多 2 步而不是 1 步：每一次四分之一轉都是角塊的一個 4-循環（奇置換），所以任何一條解的長度必定跟最短解同奇偶。走偏只會偏偶數步。

That attribution was checked separately. A* has another classic trap: testing for the goal when a child is generated rather than when it is expanded can return a non-optimal solution even with a perfectly admissible heuristic. Both variants were run over the same 500 states — both score 99.2%, and both fail on the same four states, so timing is not the cause. Those four also overshoot by exactly 2 moves, never 1: every quarter turn is a 4-cycle on the corners, an odd permutation, so any solution's length has the same parity as the optimum. Going wrong can only go wrong by an even number of moves.

一個不該有影響、但影響很大的參數

A parameter that shouldn't matter, and does

「一次拿幾個節點出來展開」（batch）純粹是為了餵飽 GPU——一次只評估一個局面， GPU 就在空轉。照理說它不該影響搜尋結果。但 2×2×2 的整棵搜尋樹才幾十到一兩千個節點： batch 一大，每一輪就把整個佇列彈光，優先順序根本沒機會發揮，搜尋退化成 BFS。

"How many nodes to pop per round" (batch) exists purely to keep the GPU busy — evaluating one state at a time leaves it idle. It should not affect what the search finds. But a 2×2×2 search tree is only tens to a couple of thousand nodes wide: make the batch large enough and every round drains the whole queue, the priority order never gets to act, and the search degenerates into BFS.

那個「保證最短解」本來就沒有

The optimality guarantee was never there

weight=1 就是課本上的 A*，定理說它保證找到最短解。實測是 ，不是 100%。差的那一點不是實作有錯， 是定理的前提沒滿足：保證成立的條件是 heuristic 不能高估， 而這個學出來的東西有 的局面高估了。 既然保證本來就不成立，把 weight 調低換速度反而是誠實的選擇。 而這整件事只有在手上有正確答案的時候才驗證得了——3×3×3 那邊只能猜。

Weight 1 is textbook A*, which the theorem says returns an optimal solution. Measured, it returns one of the time — not 100%. The gap is not an implementation bug; it is the theorem's precondition failing: optimality requires that the heuristic never over-estimate, and this learned one over-estimates on of sampled states. Since the guarantee doesn't hold anyway, trading it for speed is the honest move. And none of this is checkable without ground truth — on a 3×3×3 it would all be a guess.

同一份程式，換成三階

Same code, bigger cube

貼紙從 24 片變 54 片，轉法從 6 種變 12 種，局面數從三百六十七萬變成四千三百二十五京。 程式碼一行沒改，只有 shared/config.json 裡的網路變大、訓練變久。

Stickers go from 24 to 54, moves from 6 to 12, states from 3.67 million to 43 quintillion. Not a line of code changes — only the network size and training length in shared/config.json.

但有一件事永遠回不來了：正確答案。三階的上帝之數是 26（四分之一轉）， 可是沒有人能對一個隨手打亂的方塊說出它精確的最短解，除非跑一次大到不可能的搜尋。 所以到這裡只剩兩個問題可以問：解得開嗎？幾步？

One thing is gone for good: the ground truth. God's number for the 3×3×3 is 26 in quarter turns, but nobody can name the exact optimal solution for an arbitrary scramble without a search that is out of reach. Only two questions survive: does it solve, and in how many moves?

結果是每一個深度都 100%，包含完全隨機的 30 步打亂—— 平均 步、展開 個節點、 不到一秒一顆。對照組是 1,000 個局面各亂轉一萬步：解開 0 個。

Every depth comes out at 100%, fully random 30-move scrambles included — moves on average, nodes expanded, under a second per cube. The control, a thousand cubes turned ten thousand times at random, solved none.

那「這些解比最短解長多少」呢？精確值量不出來——但下界量得出來： 把同一批局面拿去加大搜尋力道，看解能短多少。20 顆隨機打亂的方塊， weight 從 0.3 調到 0.6、節點預算放大，只算兩種設定都解得開的那 10 顆： 平均從 24.60 步掉到 21.40 步， 9 顆變短、1 顆持平、沒有一顆變長。 也就是說實務設定的解至少比最短解長 3.2 步。 代價是 11 倍的節點、12 倍的時間，而且 20 顆裡只有一半在預算內解得完。

那 10 個差值是 4、2、6、4、0、2、4、4、2、4——全部是偶數， 跟 2×2×2 那邊同一個道理（四分之一轉是奇置換，同一個局面的所有解長度同奇偶）。 落差從哪來也看得到：網路對深局面一律回答 14 左右， 而搜尋要展開三萬個節點才走得完。那三萬個節點就是在補這個落差。

So how much longer than optimal are these solutions? The exact figure is unobtainable — but a lower bound is not: push the search harder on the same cubes and see how much shorter the solutions get. Over 20 random scrambles, raising the weight from 0.3 to 0.6 with a larger node budget — counting only the 10 cubes both settings solved — the mean drops from 24.60 to 21.40 moves: 9 shorter, 1 unchanged, none longer. So the production setting is at least 3.2 moves off optimal. The price is 11× the nodes, 12× the time, and only half the cubes finishing within budget.

Those ten differences are 4, 2, 6, 4, 0, 2, 4, 4, 2, 4 — every one of them even, for the same reason as on the 2×2×2 (a quarter turn is an odd permutation, so all solutions of a state share the optimum's parity). Where the shortfall comes from is visible too: the network answers about 14 for far states, and the search expands thirty thousand nodes to finish the job. Those thirty thousand nodes are the shortfall being paid off.

踩過的五個坑

Five things that went wrong

照論文抄門檻，訓練會靜悄悄地停住

Copying the paper's threshold silently halts training

DAVI 的 target 更新規則是「loss 掉到門檻以下，才把 target 網路往前推一版」。 論文那個門檻（0.05）放到我這個比較小的網路上，loss 根本掉不到—— 12,000 輪裡 target 只推了 10 版就再也不動，最好只到 MAE 1.35。 而訓練看起來完全正常：還在跑、loss 還在慢慢降、什麼錯都沒噴。 門檻放寬到 0.15 之後，同樣 12,000 輪推了 34 版，MAE 1.13。 同樣的程式、同樣的步數，差別只有那一個數字。 現在程式裡多了一條保險：連續幾次檢查都沒推，就強制推一版。

DAVI advances its target network only once the loss drops below a threshold. The paper's value (0.05), applied to this smaller network, sits below the loss floor — so across 12,000 iterations the target advanced 10 times and then never again, bottoming out at an MAE of 1.35. Training looked perfectly healthy throughout: still running, loss still drifting down, no error anywhere. Loosening the threshold to 0.15 gave 34 target updates over the same 12,000 iterations and an MAE of 1.13. Same code, same number of steps; one number different. There is now a fuse: after N checks with no update, advance anyway.

「平均差一步」聽起來很好，其實只比亂猜好一點

"Off by one move" sounds good until you check the baseline

這個問題八成以上的答案落在 10 到 12 之間。所以在報準確度之前一定要先問： 一個什麼都不看、永遠回答 11 的模型，誤差是多少？沒有這條底線， 任何「MAE 很小」的宣稱都不成立。真正該看的是它在兩端有沒有跟著動， 以及高估率——因為那決定 A* 還有沒有最短解的保證。

Over 80% of answers here fall between 10 and 12. So before quoting an accuracy figure, ask what a model that ignores its input and always says "11" would score. Without that baseline no "the MAE is small" claim means anything. What actually matters is whether the estimate moves at the extremes, and the over-estimation rate — because that's what decides whether A* still has any optimality guarantee left.

一個「效能參數」把演算法換掉了

A "performance knob" quietly replaced the algorithm

第一次跑 weight 對照，四個 weight 跑出一模一樣的解開率、步數、節點數—— 連小數點後兩位都一樣。看起來像 weight 沒接上去，但程式是對的。 真正的原因是批次大小：批次 200、整棵樹才一千多個節點，每一輪都把佇列彈光， 優先佇列等於不存在。一個純粹為了 GPU 利用率而設的參數， 把演算法從 A* 換成了 BFS，而且沒有任何跡象。 會抓到只是因為「四個數字一模一樣」太可疑了——如果它們只是接近，大概就這樣過去了。

The first weight sweep returned identical solve rates, lengths and node counts for all four weights — matching to two decimal places. It looked like the weight wasn't wired up. The code was fine. The cause was the batch size: with batch 200 against a tree of about a thousand nodes, every round drained the queue and the priority order never applied. A knob that exists only for GPU utilisation had swapped A* for BFS, silently. It got caught only because four identical numbers are too suspicious to ignore — had they merely been close, it would have shipped.

沒有正確答案，連「挑哪個 checkpoint」都會挑錯

Without ground truth, even picking a checkpoint goes wrong

2×2×2 有精確答案，「哪一版最好」直接用 MAE 決定。3×3×3 沒有，就退而求其次用 loss—— 於是存下來的「最佳」權重是第 2,000 輪那一版。 因為 DAVI 訓練最初期的 loss 就是最低的：那時候 target 網路幾乎是個常數， 「猜一個固定的數字」當然很好擬合。這個標準挑的是「最什麼都還沒學會」的那一版， 而且它一路蓋掉了後面四萬五千輪的成果。會抓到，是因為去看了一眼 checkpoint 裡的輪數。 這一條跟整頁的主題其實是同一件事：沒有 ground truth，少掉的不只是 「它有多準」，連「哪一版比較好」都跟著不見。

On the 2×2×2, "which version is best" is settled by MAE against exact truth. The 3×3×3 has none, so the fallback was loss — and the checkpoint saved as "best" turned out to be from iteration 2,000. DAVI's loss is at its lowest right at the start, because the target network is then almost a constant and predicting a fixed number fits beautifully. The criterion selects the version that has learned the least, and then keeps overwriting forty-five thousand iterations of progress with it. It surfaced only from glancing at the iteration number stored in the file. Which is the same lesson as the rest of this page: without ground truth you lose more than "how accurate is it" — you lose "which one is better" too.

把「取樣打亂 k 步」當成「距離 k」

Confusing "scrambled k moves" with "k moves away"

亂轉 14 步的方塊，真實距離往往遠小於 14——繞回來了。用「亂轉 k 步」抽出來的局面去做 benchmark，會系統性偏向簡單的局面，數字自然好看。既然整張距離表都算出來了， 2×2×2 的評估就該從全部 3,674,160 個裡均勻抽。這頁上的 2×2×2 數字都是這樣抽的。 3×3×3 沒有這個選項，所以那張表只能照打亂深度分組——並且明講這件事。

A cube scrambled 14 moves is usually much closer than 14 — the walk loops back. Benchmarking on states drawn by "scramble k moves" quietly biases toward easy states and flatters the numbers. Since the full distance table exists, the 2×2×2 evaluation samples uniformly from all 3,674,160 states, which is what every 2×2×2 figure on this page does. The 3×3×3 has no such option, so its table is grouped by scramble depth — and says so.

One closing note. In the previous five labs the network learned what to do. Here it does nothing at all — it only judges how far away something is. Separating judgment from decision is precisely what lets the same method carry from three million states to forty-three quintillion.
